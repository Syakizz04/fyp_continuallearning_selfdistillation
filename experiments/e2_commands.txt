5. WHEN IT FINISHES - CHECK BEFORE TRUSTING THE NUMBERS
-------------------------------------------------------------------------------

    cd /workspace/fyp
    cat outputs/drift/results/e2/e2_summary.csv

Expect 12 rows (one per censoring x arm). Then verify:

  a) frozen shows forgetting_mase_base_era EXACTLY 0 in every cell.
     It is the anchor; anything else means the tables were built against the
     wrong reference.

  b) frozen is IDENTICAL across all three censoring levels. It never retrains,
     so it never ingests censored data. If it moves, censoring has leaked into
     the evaluation path.

  c) naive / replay / sdft all show NON-ZERO retrain counts. Zero means no
     drift fired and every arm is secretly frozen.

Headline column: forgetting_mase_base_era   (>0 = the arm lost pre-drift
knowledge). NOT walk_mase_mean - mean walk error confounds adapting to the new
regime with retaining the old one, and the second is the question.

Also worth reading:
    cat outputs/drift/results/e2/none/k_sensitivity_rl_sdft.json
    cat outputs/drift/results/e2/none/k_sensitivity_sdft.json
These show what every other drift threshold would have triggered - the evidence
that k=2.0 (forecasting) and k=1.5 (RL) were not arbitrary.

-------------------------------------------------------------------------------
8. E5 - THE SDFT ALPHA SWEEP
-------------------------------------------------------------------------------
6 cells = 2 censoring (none, escrow_quota) x 3 alphas (0.7, 0.85, 0.95).
alpha=0.5 is NOT re-run - E2 already measured it, and it is the baseline.

REQUIRES E2's results on disk: each cell copies E2's frozen probe scores in as
the forgetting anchor (frozen never retrains, so it is invariant to both alpha
and censoring - copying avoids six identical walks). If you are on a fresh box,
upload results.tar.gz and extract it at the project root FIRST:
    tar -xzf results.tar.gz          # restores outputs/drift/results/e2/

Check the plan without loading models (also verifies the anchor is present):
    python -m experiments.exp_sdft_alpha --dry-run

Run:
    CONCURRENCY=6 bash experiments/run_e5.sh

Progress - the monitor understands this layout too:
    python -m experiments.monitor_e2 --layout e5
    python -m experiments.monitor_e2 --layout e5 --once

VRAM is the constraint here, not cores: every E5 cell is an SDFT cell, and
self-distillation keeps a frozen TEACHER resident alongside the student, so a
cell costs ~2.5-3 GB rather than E2's ~1.5 GB average. Six concurrent cells
OOM'd a 15 GB card. Budget ~3 GB per concurrent cell and watch:
    nvidia-smi --query-gpu=memory.used --format=csv
An OOM is recoverable - the cell resumes from its last checkpoint on relaunch -
so the fix is just a lower CONCURRENCY, not a restart from zero.

Read the result:
    cat outputs/drift/results/e5/e5_summary.csv

What it answers - compare against E2's numbers at the same censoring level:
    walk_mase_mean            replay ~1.02, frozen 1.474, sdft@0.5 ~1.42
      -> does it fall toward replay as alpha rises? that is the viability test
    forgetting_mase_base_era  naive 0.139 (none) / 0.053 (escrow_quota)
      -> does it stay BELOW naive? if not, the mechanism adds nothing over
         plain fine-tuning
    if the best alpha DIFFERS between none and escrow_quota, that is a real
    finding about self-distillation under endogenous label corruption

Same recovery rules as E2: resumable, do not pass --force, pull results off
before destroying.

REUSABLE MODELS: each cell writes its trained model to
    outputs/drift/results/e5/<censoring>/alpha_<a>/model/
as a normal checkpoint directory (~12 MB: base_tft.ckpt, base_tft_dataset.pkl,
base_ppo.zip, base_meta.json, calibration.json). The SDFT teacher is stripped,
so it loads through the ordinary loader with no special handling:

    from drift_pipeline import monitor as mon
    from experiments.exp_staleness_cl import base_paths
    base = mon.load_base(base_paths(Path('outputs/drift/results/e5/escrow_quota/alpha_095/model')))
    fc, ppo = base['forecaster'], base['pricer']

Or serve it from an edge node without code changes:
    FYP_BASE_CKPT_DIR=outputs/drift/results/e5/escrow_quota/alpha_095/model \
        python -m edge_system.run_system

base_meta.json records which alpha produced it under "provenance". Disable with
--no-save-model if you only want the metrics.

These are included in the results tarball, so it will be ~80 MB rather than
~200 KB. Worth it - the walk's models exist only at the moment they are scored
and are otherwise dropped.

NOTE: running preflight standalone will FAIL the Thread budget check, because
OMP_NUM_THREADS is only set by run_e2.sh. That is expected - prefix it as above
to test, or just launch and let run_e2.sh handle it.
